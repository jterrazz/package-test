# Glossary

The words this manual uses, one meaning each.

| Word                | Means                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| ------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| kind, specification | A kind of test: api, cli, website ... A **specification** is the code behind one kind: its constructor (`specification.api()`), its chain and its result, composed in `src/specifications/<name>/<name>.composition.ts`. It is not the `kind` a repository declares in `jterrazz.config.ts`: the two agree by design (a repository of kind `api` is specified by the `api` specification) but stay distinct, since a kind says what the repository IS (its build, its presets) and a specification says how a test drives it, so a `library` holds `cli` or `lint` specifications |
| module, unit        | The kind that tests one module, from the `__tests__/` of its folder, is a **module** test; the vitest project and the specification that run it are named `unit` (`test.projects.unit`, `--project unit`)                                                                                                                                                                                                                                                                                                                                                                         |
| runner              | What a constructor returns, such as `api` from `specification.api()`: the object every chain of the suite starts from                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| handle              | What a service factory returns, such as `postgres()`: the service before it starts, then its `connectionString` once it runs                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| chain               | One test's sentence on a runner: zero or more setups (`.seed()`, `.intercept()` ...), then exactly one action (`.get()`, `.exec()` ...) that resolves to a result                                                                                                                                                                                                                                                                                                                                                                                                                 |
| oracle              | What a test compares the result against: the value inside `expect(...).toMatch(...)`                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| golden              | An oracle kept in a file under `__expected__/`, compared whole and rewritten by `TEST_UPDATE=1`                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| ground              | The files a test stands on, in the `__seeds__/`, `__requests__/`, `__fixtures__/` and `__expected__/` folders                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| seam                | A place where the framework meets an outside tool it loads on demand: a database driver, a browser, a simulator. Each is an optional peer                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| ratchet             | A count of debt kept in `.jterrazz/baseline.json` that may only fall: an unreached route, a convention not yet followed. A run that raises it fails, and `TEST_UPDATE=1` records a fall                                                                                                                                                                                                                                                                                                                                                                                           |
| specimen            | A small sample app a testing tool keeps under `specs/__fixtures__/` to test itself against. Only a repository that tests a testing tool has one                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| door                | Where a test file may sit: in the `__tests__/` of its module's folder (a unit), under `specs/<kind>/` (an assembled product), or in a repository suite (the third door)                                                                                                                                                                                                                                                                                                                                                                                                           |

The examples use made-up products: `shoply`, a shop CLI; a news app with an events feed; and hosts under `.test` and `.example`, which never resolve on the internet.
